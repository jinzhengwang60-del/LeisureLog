# 源码运行与升级

[项目首页](../README.md) · [回退说明](plugin-rollback.md) · [插件管理](plugin-management.md)

当前源码包含“核心 + 官方插件”实现。源码启动与 Windows 安装版具有不同的数据路径；本次更新只发布源码，不提供新安装包。

## 从源码启动

按项目首页准备 Python 3.11+ 环境、安装依赖、复制 .env.example 并执行 Alembic 迁移后，从项目根目录启动。

| 入口或资料 | 默认位置 |
|---|---|
| 启动 | start-leisurelog.bat |
| 停止、更新后重启 | stop-leisurelog.bat、restart-leisurelog.bat |
| 首页 | http://127.0.0.1:8001/ |
| 插件管理 | http://127.0.0.1:8001/plugins |
| 活动数据库 | data/leisurelog.db，结构 0013 |
| 规则 | config/rules.yaml |
| 游戏库导出 | data/playnite-library.json，需独立连接 Playnite |
| 插件选择 | 默认在数据库旁的 plugin-state.json；可用 LEISURELOG_PLUGIN_STATE_PATH 显式指定 |

首次没有插件选择文件时，两个官方模块默认启用以延续已有游戏功能。通过管理页面修改后保存选择；重启不会把已停用或撤销的权限自动补回。没有 Playnite 时，ActivityWatch 原始记录和 Session 仍可继续生成。

公开进程绑定为通用空模板，不包含个人游戏库。请按自己的实际程序与窗口标题添加绑定；共用进程需要额外标题条件。

## 从更新前的源码升级

1. 保存源码改动，记录运行目录、数据路径与当前提交，创建并验证完整备份。
2. 停止原 LeisureLog；ActivityWatch 可以继续独立记录。
3. 获取新版源码，在原虚拟环境更新项目安装登记和需要的依赖。现有环境文件、数据库、规则和游戏资料继续使用。
4. 核对 Alembic 版本。本次与原 v0.4.0b1 同为 0013，无新增数据库迁移，不需要全量历史重算；更早版本仍需按对应说明迁移。
5. 使用原启动脚本启动，确认 /health 返回 ok / 0013 / 0.4.0b1，/api/plugins 中两个官方功能正常或符合保存的停用选择。
6. 查看自动同步最近成功时间、历史记录和人工修正，再创建一份新版完整 ZIP 备份。

源码版本字符串仍为 0.4.0b1；请用 Git 提交及插件接口辨别此次更新。不要同时启动两个实例写入同一库，也不要为了程序回退覆盖旧数据库快照。恢复旧程序见 [回退说明](plugin-rollback.md)。

## 验证与能力边界

公开源码与日常使用版的业务代码、迁移、网页资源和测试保持一致，个人配置、维护记录和本机路径不公开。复测使用合成输入与隔离临时数据库，不读取真实活动资料，方法与实际结果见 [验证记录](verification.md)。

插件管理用于已显式登记的官方功能。独立包安装、下载市场、任意第三方代码强隔离均未实现；线程预算和授权检查不能当作系统沙箱。
