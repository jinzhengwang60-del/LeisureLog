# 活动用途与项目（v0.2）

[返回项目首页](../README.md)

本页介绍基础归属架构。当前 v0.3 新增的待确认中心、影响预览、解释、撤销、累计投入目标和 0013 升级说明见 [新版使用说明](confirmation.md)。

LeisureLog 记录电脑上的主要前台活动。游戏和娱乐是活动的一部分；文档、代码、课程、网页与沟通同样进入首页、统计和周回顾。

## 三个独立维度

| 维度 | 例子 | 用途 |
|---|---|---|
| 活动类型 `classification.category` | 视频、游戏、阅读、编程、文档 | 描述活动内容，沿用原有分类体系 |
| 用途 `context.purpose` | 工作、学习、创作、沟通、娱乐、系统操作、其他、待确认 | 描述为什么进行这段活动 |
| 项目 `context.project_id` | LeisureLog、毕业论文、视频制作 | 把多个应用中的时间归到同一件事上，可不关联 |

例如一段 B 站视频可以是“视频 / 学习 / 毕业论文”，代码编辑器可以是“编程 / 工作 / LeisureLog”。类型、用途和项目分别保存；修改用途或项目不改动原始数据和原有的内容纠错。

默认用途保持保守：明确的游戏、影视与音乐可以归为娱乐，已有工作分类归为工作；视频、阅读、浏览器、代码和文档没有一个通用的真实目的，未命中用途规则时保留待确认。`config/rules.yaml` 中独立的 `purpose_rules` 可以补充用途，示例包括 Anki 学习、OBS/Blender 创作和 Zoom 沟通。

## 开始使用

1. 打开导航里的“项目”，创建名称、说明和标记颜色。
2. 回到“活动记录”，点击某条记录的“查看”，在“用途与项目”中选择归属并保存。
3. 大量已有记录可以勾选多条或“选择本页”，再点击“批量修改归属”。未修改的字段保持原值，一次最多处理 1000 条来源记录。
4. 自动关联范围默认“仅修改这次记录”。选择标题、关键词、网页地址、网站或应用后，会记住规则，同时更新已有匹配记录和未来导入的活动。
5. 在首页按用途或项目筛选，在“统计与趋势”里按周、月、年或自选日期查看，并导出当前筛选的每日/月度统计 CSV。

首页顶部的总览始终表示整个当天；下方数据明细、列表与时间带随筛选变化。项目页会按活动发生日期统计，片段之间的空档不计为项目时间。项目详情提供应用、用途及日期分布，点击日期可以回到对应记录。

## 规则与人工选择

用途和项目分别决定优先级：**人工指定 > 记住的归属规则 > 配置用途规则 > 保守类型默认 > 待确认/未关联**。

规则范围含义：

- 同一应用：同一来源、同一应用的记录；浏览器不允许用整个应用一概归属。
- 同一标题：完整标题精确匹配。
- 标题含关键词：同一来源、同一应用，标题包含指定的 2–300 字符关键词，忽略大小写。适用于文件名变化但标题保留项目名的编辑器或网页。
- 同一网页地址：URL 去除 fragment 后匹配，保留 query。
- 同一网站：精确匹配 hostname，不自动扩大到所有子域名。

具体 URL 优先于完整标题，随后是关键词、网站和应用。关键词冲突时较长关键词优先，同等精度最近保存的规则优先。可以分别从不同应用保存指向同一项目的规则。

首页“数据与设置 → 用途与项目规则”，以及项目页“自动关联规则”，可以查看和删除规则。删除会重算自动归属，人工指定保持有效。“恢复自动归属”撤销所选记录的人工用途和项目，已有规则仍可命中；“恢复自动用途”只撤销用途，保留项目。明确选择“不关联项目”属于人工决定，会优先于自动项目规则。

新记录可以继承原窗口的人工归属，例如浏览器扩展后来补齐网页信息时。对某个网页片段单独恢复自动归属，不会删除同一原窗口其他片段的人工选择。

## 项目生命周期与统计口径

项目支持修改名称、说明、颜色以及归档。归档保留历史关联和现有规则；新手动选择的列表隐藏已归档项目。需要停止后续自动关联时，删除相应规则。当前不提供永久删除项目的接口。

“用途待确认”与“状态待确认”独立：前者表示目的未知，后者表示没有对应的键鼠活动状态。两者均保留在活动总时间内。用途/项目不改变现有计时策略，也不把项目时长解释为产出或效率。

前台窗口仍是计时来源，网页数据只补充内容；没有新增后台进程采集，也没有跨设备时间排重。云端同步、AI 分类与手机端不包含在 v0.2。

## 数据与扩展

`ActivityContext` 随派生的 `ResolvedActivity` 和 `Session` 保存；每日事实增加 `purpose` 与 `project_id`，用于范围 SQL 汇总。项目元数据在 `activity_projects`，人工归属在 `context_overrides`，归属规则在 `context_rules`。原始源快照不增加用途/项目字段。

`ContextClassifier.classify_context(event)` 是独立的可插拔接口，每个分类器可以只提供用途或项目，不用同时决定两项。领域计算在 `domain/activity_context.py`，业务用例在 `services/activity_context.py`，持久化在 `repositories/activity_context.py`，项目与周分析在 `analytics/`，组装和事务在 `api/` 与 `main.py`。

## 升级与回退

迁移 **0012** 新增三张表、派生记录的 context 以及每日用途/项目字段和查询索引，不改动原始记录与既有人工内容分类。已运行的旧版本升级顺序：先创建并验证完整备份，停止旧服务，执行 `alembic upgrade head`，启动新版，再执行一次 `POST /api/reprocess` 回填已有记录的用途。重新处理不依赖 ActivityWatch 在线。

应用启动不自动执行数据库变更。健康检查应返回 `status=ok`、`database_revision=0012`、`version=0.2.0`。升级之前的 0011 备份可在独立数据库恢复，再迁移和重处理。

回退到 0011 会移除新增的项目、归属规则、人工归属与相关派生字段；原始数据和旧版的人工内容分类保留。要保留 v0.2 的归属资料，请保留升级后的完整备份，并使用与数据库版本一致的代码。迁移使用 SQLite 3.35+ 的原生列删除，避免重建已有外键引用的父表。

自动备份依赖同步成功的问题已在 v0.3 修复，其余三项见 [待修复清单](development.md)。旧版周回顾的深夜/最长片段字段为兼容接口保留，周回顾页面使用全部活动、用途与项目指标。
