# 稳定性收尾与维护

本轮以现有功能可靠运行、数据可以恢复、以后可以继续维护为目标。
保留模块化单体和“核心 + 官方插件”的边界，不增加第三方市场、云同步或新的业务模块。

## 验收范围

- 周回顾按实际区间计算凌晨时间，保留人工计时和分类的优先级；连续 Session 在一周内跨日累加，周界外不计入。
- 手动与自动同步都先读取完整来源批次，再进入宿主写事务；上游慢响应不占用数据库写锁，失败不提交半批数据。
- 损坏的备份说明不会让整个备份列表或自动备份失效；保留异常文件供人工检查，轮换不删除它们。
- 提供校验后恢复到新目录的工具，拒绝覆盖现有目录；不自动替换正在使用的数据库。
- 长期运行的服务日志有大小与数量上限；使用说明涵盖启动、来源离线、备份、恢复和停用插件。
- 全部后端、前端脚本和架构检查在本轮重新执行；保留旧版本和新版本回退点。

数据库结构继续使用 `0013`，本轮不要求迁移或重算历史。统计读取修复直接生效，已有人工选择和原始记录保留。

## 回退与后续边界
