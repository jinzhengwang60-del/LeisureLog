# 待确认、规则预览与项目投入目标（v0.3）

[返回项目首页](../README.md)

这一版把用途整理接成一个完整流程：找出待确认的活动 → 指定用途或项目 → 预览自动规则 → 保存 → 查看来源或撤销。活动采集、内容分类和计时继续独立运行。

## 从待确认页面开始

导航里的“待确认”默认展示用途尚未确定、且有计入时间的活动。选择周、月、年或自选日期，也可以搜索应用或网站。普通应用按来源和应用分组，浏览器按网站分组；同一浏览器中的不同网站可以分别指定用途。

分组按待确认时间从多到少排列，每页最多 40 组。点击“确认用途”会读取该组最近的最多 1000 条待确认记录，选择用途、项目或两者。没有项目不属于错误，也不会因此反复进入待确认。

保留“活动类型”标签页，用于原有的应用内容分类。用途与活动类型独立：视频可以用于学习，编程可以用于工作或兴趣项目。AFK 和计时策略沿用原来的规则，零计入时间的分组不占用确认列表。

日期限定待确认列表和时间汇总。归属以整条来源记录为单位保存，跨午夜的记录可能同时改变相邻日期。超过 1000 条的分组可以分批处理；选择自动关联规则后，其影响范围是全部历史，不限于页面选定日期。

## 保存规则前先看影响

自动关联范围默认“仅修改这次记录”。如果选择记住应用、完整标题、标题关键词、网页地址或网站，保存按钮会先变为“预览规则影响”。预览展示：

- 全部历史中匹配的来源记录数。
- 真正会改变用途或项目值的记录数；仅来源标记变化不算改变归属。
- 未选中且保留已有人工指定的记录数。
- 最多六条样例的原归属、新归属，以及是否保留人工选择。

预览是只读操作，不保存规则或修改记录。核对后再点击“确认规则并保存”。修改用途、项目、范围或关键词会清除旧预览。预览后活动数据或影响结果变化时，保存返回 409，页面要求重新预览，旧选择不会写入。

规则按字段分别计算优先级：人工指定 > 已记住规则 > 配置用途规则 > 按活动类型推定 > 未确定。已记住规则依次比较 URL、完整标题、标题关键词、网站、应用；较长关键词优先，相同精度较新的规则优先。浏览器不能保存整个应用的用途规则。

选中的记录属于这次明确的人工修改，可以覆盖它们自己的旧人工归属；其他记录的人工归属继续保留。用途和项目可以来自不同规则，修改一个字段不会覆盖另一个字段。

## 为什么这样归属，以及如何撤销

活动详情中的“为什么这样归属？”分别说明用途和项目的来源：人工指定、哪条已记住规则、哪个配置用途规则、按类型推定或尚未确定。一个片段包含多条来源记录时，说明明确针对第一条记录。

首页“数据与设置 → 规则与修改记录”、待确认页面和项目页面都提供规则与修改记录入口。v0.3 开始保存以下操作的撤销资料：指定用途/项目、保存规则、恢复自动归属、删除归属规则。旧版操作没有事前快照，不会补造撤销记录。

撤销会恢复该次操作之前的人工归属和规则，并重新计算派生统计。它保留原规则的保存时间和优先顺序，也支持原窗口后来被网页信息拆分成多个片段的情况。原始快照、人工内容分类和人工计时选择不由这个撤销功能改写。

若同一人工归属或规则后来又被修改，直接撤销较旧操作会返回 409；需要先撤销相关较新的修改。已经撤销的操作不能重复撤销。修改记录按页查询，不会在页面读取全部历史；撤销资料随数据库和完整备份一起保存。目前不提供“重做”，重新指定归属即可。

## 项目投入目标

新建或编辑项目时，可以填写可选的“累计投入目标（小时）”，留空可取消目标。项目卡片和详情展示累计投入、目标、比例、还差多少以及是否达到目标。

目标使用该项目全部历史的计入活动时间。页面日期只影响当期活动统计，不改变累计目标进度。活动之间的空档不计入，AFK 按既有策略扣除或保留。超过目标时比例可以超过 100%，进度条显示到满格。

目标表示希望投入的时间，不表示任务完成率或工作效率。归档保留目标及历史；修改名称或说明的旧 API 客户端未发送目标字段时，也会保留已有目标。

## 独立自动备份

自动备份现在由独立的定时任务检查，不依赖 ActivityWatch 同步成功。关闭自动同步或 ActivityWatch 离线时，运行中的 LeisureLog 仍然会检查备份是否到期。

默认每七天创建备份，保留最近四份自动备份，手动备份继续保留。启动服务时检查一次，此后默认每小时检查；LeisureLog 没有运行时不会执行后台任务，下次启动时补做检查。存储页面显示实际配置、最近检查时间和错误状态。

`LEISURELOG_AUTO_BACKUP_CHECK_SECONDS` 可以调整检查间隔，默认 3600，允许 60–86400 秒。这个值决定检查频率，不改变备份的天数间隔。备份失败由备份任务报告和重试，不阻断活动同步。恢复和完整性验证见 [存储与备份](storage.md)。

## 模块与接口

| 模块 | 职责 |
|---|---|
| `domain/activity_context.py` | 可插拔用途分类器、规则匹配、人工优先和存储协议 |
| `services/activity_context.py` | 只读影响预览、归属修改、解释和带冲突检查的撤销 |
| `repositories/activity_context.py` | 项目元数据、人工归属、规则与撤销快照、SQL 分组和分页 |
| `analytics/confirmation.py` / `analytics/projects.py` | 待确认范围验证、展示用汇总、累计投入目标 |
| `adapters/scheduler.py` / `services/storage.py` | 独立定时任务与备份用例 |
| `api/activity_context.py` / 静态资源 | API 校验、事务入口和本地页面交互 |

新增接口：

| 方法与地址 | 用途 |
|---|---|
| `GET /api/activity-context/pending` | 按日期、应用/网站搜索并分页列出待确认分组 |
| `GET /api/activity-context/pending/events` | 分页读取指定分组的来源记录 |
| `POST /api/activity-context/preview` | 只读预览，返回匹配数、改变数、样例和 `preview_token` |
| `PUT /api/events/context` | 保存归属；页面保存规则时携带预览令牌 |
| `GET /api/events/{id}/context/explanation` | 查询用途和项目来源及匹配规则 |
| `GET /api/activity-context/changes` | 分页读取可撤销修改 |
| `POST /api/activity-context/changes/{id}/undo` | 原子撤销；过期或冲突返回 409 |
| `POST/PUT /api/projects[/id]` | 可选 `goal_seconds`，正数或 `null` |
| `GET /api/storage` | 包含独立自动备份任务状态 |

兼容旧调用者：归属写入接口的 `preview_token` 仍是可选字段，本版网页保存自动规则时必须先预览。接口提供只读事务依赖，预览不会抢占 SQLite 写锁；写入先取得写锁，提交后才返回成功。

数据库迁移 **0013** 只新增可空的项目目标字段和归属修改记录表，不改写原始/处理活动及已有人工选择。先备份，再执行 `alembic upgrade head` 并重启服务；健康检查应为 **0.3.0 / 0013**。回退 0012 会删除目标和撤销历史，要保留它们请保留完整备份。
